I am happy to say my chat bot is finally finished (well for now anyway): themeparks-bot answers questions about theme parks worldwide such as rides, park opening hours and wait times.

themeparks-bot was built using Microsoft Bot Framework with Node and TypeScript; and given what I know now I thought I would put a bot starter project together and discuss some of the key parts.

Choosing a web framework

When getting started with Microsoft Bot Framework, you need to choose a web framework to use. The Bot Builder samples I looked at either use express or restify.

I chose to use express since I had previous experience with it, but to be honest it doesn’t really matter which web framework you use; since it is only used in a small part of the bot to create an API endpoint.

Use libraries to structure dialogs

Bots in Microsoft Bot Framework are made up of dialogs, akin to screens in single page applications, each containing separate logic and ideally responsible for a single purpose such as asking a question to a user.

Use a storage service for state

At some point a bot will need to persist state such as remembering that it has seen a user before.

This requires bot storage to be configured; by default Microsoft Bot Framework uses in-memory storage however this is only intended for testing. Therefore for production, one of the supported storage mechanisms i.e. Cosmos DB, Table Storage or SQL needs to be used.

The starter project uses Table Storage and the set up is shown below:

The bot storage is configured this way in order that during development in-memory storage is used whereas in production, table storage is used. That way the Table Storage account doesn’t get filled up with development/test data.

Use dotenv for configuration

There are a number of configuration settings used throughout the bot such as Table Storage credentials, LUIS endpoint and Microsoft App credentials.

These are set at development time using dotenv as described in an earlier post.
